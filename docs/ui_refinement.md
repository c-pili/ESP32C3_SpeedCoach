# ESP32-C3 SpeedCoach — current firmware

This document describes the active C3 firmware. Older touchscreen, S3, USB mass-storage, interval-workout, race-pacing, and step-test UI plans have been removed.

## Hardware and controls

- ESP32-C3 with MPU6050 on I2C, NEO-M8N on UART1, and Sharp LS027 400×240 reflective monochrome display.
- The display has no touch input. The PWR key starts a normal activity on a short press, stops and saves it on the next short press, and saves then powers off on a five-second hold.
- The dashboard remains on pace, elapsed time, stroke rate, heart rate, and distance.
- Heart rate is received automatically from the saved BLE heart-rate sensor. No UI pairing screen is required for the normal Suunto auto-discovery path.

## Activity storage and export

Activities are written to internal SPIFFS under `/spiffs/activities`. Each activity contains stroke CSV, split CSV, and `Workout.tcx`. While idle, the device advertises `SpeedCoach_Wi-Fi`; connect with password `SpeedCoach` and open `http://192.168.4.1` to download TCX files. The AP stops during recording and returns after the files are closed.

The custom partition table reserves the `storage` partition in a 4 MB flash layout. The first SPIFFS image is generated by the build and must be written to that partition once. Routine firmware flashing does not overwrite activity data.

## Runtime ownership

`stroke_task` reads the MPU6050 at 100 Hz, updates the activity model and publishes immutable metric snapshots. LVGL applies snapshots on its own task. BLE callbacks do not call LVGL. The Wi-Fi HTTP server serves completed activity files while recording is idle.

## Build

Use the ESP-IDF version pinned by `main/idf_component.yml` and the component versions in `dependencies.lock`:

```text
idf.py set-target esp32c3
idf.py build
idf.py flash monitor
```

Confirm the board's GPIO wiring against the pin table in the project README before connecting hardware.
